int32 整型除法优化，当前 AscendNPU-IR 中仅针对 2^n 被除数做了 fastpath 优化，而对于更加一般的 k*2^n 的情形只能走模版库软实现。软实现带来的问题是，会出现大量标量指令和寄存器 spill 引发性能回退，尤其在 mcf 影响融合策略之后该问题进一步被暴露

> 具体算法原理参考 LLVM 社区实现 `SignedDivisionByConstantInfo` 和 `UnsignedDivisionByConstantInfo`

## 算法实现

对于任意无符号除法：`q = x / d, r = x % d`，其中 `d` 是一个编译期常量，我们可以生成如下值：

- `P = 2^p`
- `M = ceil(P/d)`
- `e = M*d - P`

则原始的 `x * 1/d` 中的 `1/d` 的近似值是 `M/P`，进而 `x/d = x*M/P`。由于 `x = q*d + r`，`0 <= r < d` 以及 `M = (P + e) / d`，则可以推导出如下等式：

```
x*M/P = x*(P+e)/(P*d) = x/d + x*e/(P*d)
                      = q + r/d + x*e/(P*d)
```

等式中最后一项是使用定点倒数产生的偏差，为了使得结果正确，我们需要保证：

```
r/d + x*e/(P*d) < 1
=> rP + x*e < P*d
=> xe < (d - r)*P
```

整个表达式需要证明的就是 `x/d < q+1`，这样向下取整就仍然能够得到正确的 `q`

给定一个 `P`，能够计算出 `M` 和 `e`。而由于 `x` 是 32bit 整数，因此：

1. `x < 2^32`，从而 `x*e < t`，`t` 是一个能够计算出来的近似值
2. `d > r` => `P < (d-r)*P`

进而，若 `x*e < P` => `x*e < (d-r)*P`。因此只需要枚举 P 的值，对于一个确定范围的 `x` 总是能够找到多个 `P` 的解，最终只需要使用其中解集中的其中一个解作为 `P` 的最终值即可。相关实现可以直接从 llvm 函数中获取

---

由于 `M = ceil(P/d)` 有可能超过 32bit，即 `M = 2^32 + s`，此时 `x*M/P = x*(2^32 + s)/P = (x*2^32 + x*s)/P`

结合 hivm 中提供的 op，当前 hivm 语义中提供了 `umulhi(a, b)` op，该 op 能够计算 `a*b` 并且取高 32bit 的值，相当于右移了 32 位

因此最终 `x*M/P` 等价于 `(x + h)/(p/2^32)` 其中 `h = umulhi(x, s)`。进一步的，由于 `x + h` 可能会溢出，因此 `x + h = h + (x - h)/2`，最终等价于生成如下指令：

```c++
// 若 x*M 不发生溢出
h = umulhi(x, M);
q = h >> log2(M/2^32)

// 若 x*M 发生溢出
// q = n*M_full/2^(32+s)
// M_full = 2^32 + M
// q = (x + h)/2^s
h = umulhi(x, M);
h = h + ((x - h) >> 1);
q = h >> (s - 1);
```
